# CLAUDE.md — 2D-FIGHT

A KOF XIII-class 2.5D fighting game built in Three.js. Target: beat *The King of
Fighters XIII* in a **blind side-by-side visual comparison**.

---

## 0. Operating rules for this container (READ FIRST)

This session runs in an **ephemeral container on Anthropic infrastructure that can
be stopped at any time**. Nothing survives except what is committed and pushed.

### Workflow discipline

1. **Prefer short workflows over long ones.** Split `dev` and `verify` into
   separate workflow invocations. A workflow that runs >15 min is a workflow that
   will get killed halfway. Target ~5–10 min per invocation.
   **This box has 4 cores, so the workflow concurrency cap is 2.** A "parallel"
   wave of 6 agents actually runs three pairs back to back. Size waves at 4–6
   agents and expect them to serialize — a 10-agent wave is a 40-minute workflow
   wearing a costume, and it will get killed.

   **Scope each agent to one deliverable.** Wave A proved the failure mode: the
   "engine" and "textures" agents were each given a whole subsystem and ran ~2
   hours, while the three narrowly-scoped agents finished in ~20 minutes. An
   agent asked for seven files will take seven times as long as one asked for
   one, and it is the long agents that the container kills. Split by file, not
   by subsystem.

   The Monitor `persistent: true` flag does **not** lift the 30-minute cap —
   monitors time out and must be re-armed. Expect to re-arm once per wave.
2. **Always set a wakeup timer when a workflow is running.** Use
   `ScheduleWakeup` (dynamic `/loop` mode) with a fallback heartbeat of
   1200–1800s. On wake: call `TaskList`; if the workflow is gone/dead and its
   work is unfinished, **restart it** (`Workflow({scriptPath, resumeFromRunId})`
   resumes from the longest unchanged prefix — cached agents return instantly).

3. **Agents must not hang, and hangs must be detected.**

   *Detection*: arm the watcher on every workflow launch. It watches agents
   append to their transcripts and shouts when that stops — the failure mode a
   completion notification can never catch, because a wedged agent keeps the run
   nominally "alive" forever.

   ```
   Monitor({ command: "tools/workflow-watch.sh <workflow-transcript-dir> <agent-count> 420",
             persistent: true })
   ```

   The transcript dir is in the Workflow tool result. On a `STALL` event: read
   the newest `agent-*.jsonl` to see what it is stuck on, `TaskStop` the
   workflow, then resume with `resumeFromRunId` so finished agents return from
   cache and only the wedged one re-runs.

   *Prevention*: every workflow prompt must carry the *no blocking commands*
   rule below. The killers are a foreground dev server, an interactive prompt,
   and an unbounded wait — all of which look like normal commands right up until
   nothing ever returns.
3. **Every workflow's script path is persisted** under the session dir and
   returned in the tool result. Record it in `docs/PROGRESS.md` so a restarted
   session can resume rather than redo.
4. **Commit and push after every workflow completes.** Never let more than one
   workflow's worth of work sit uncommitted. `git push -u origin claude/kof-xiii-fighting-game-rtjm7a`
   with exponential backoff (2s/4s/8s/16s) on network failure.
5. **`docs/PROGRESS.md` is the source of truth for resuming.** It records: what
   is done, what is in flight, the last workflow run IDs, and the critic scores.
   A fresh session should be able to read it and continue with zero context.

### The no-blocking-commands rule (paste into every workflow prompt)

> Never run a command that does not return on its own. Specifically:
> - **No foreground dev server.** `npm run dev`, `vite`, `vite preview`, `python
>   -m http.server` never exit. If you need the app running, use the capture
>   harness (`node tools/shots/capture.mjs`), which starts and stops its own
>   server, or launch with `run_in_background: true`.
> - **No `playwright install`** — Chromium is preinstalled; that command downloads
>   for minutes and may hang on the egress proxy.
> - **Wrap anything that touches the network or a browser in `timeout`**, e.g.
>   `timeout 180 node tools/shots/capture.mjs ...`. A hung browser launch is the
>   single most common wedge.
> - **No interactive commands** — no `git rebase -i`, no `npm init` without `-y`,
>   nothing that opens a pager. Set `GIT_PAGER=cat` if you shell out to git.
> - **No `tail -f`, no `watch`, no unbounded polling loops.**
> - Prefer the Read/Edit/Write/Grep tools over shell equivalents; they cannot hang.

### Recovery checklist after a container restart

```
git log --oneline -10          # what landed
cat docs/PROGRESS.md           # what was in flight
npm ci && npm run build        # confirm the tree is green
npm run shots                  # regenerate screenshots
```

## 1. Hard constraints

- **Every asset is generated by us, in code.** No downloaded textures, meshes,
  fonts, audio files, or reference images ship in the game. Procedural synthesis
  only: noise-based texture generation, code-authored meshes and rigs, WebAudio
  synthesis. Reference images may be *looked at* for art direction; they must
  never become assets.
- **Three.js**, TypeScript, Vite. No game-engine dependency.
- **Deterministic simulation.** Fixed 60 Hz timestep, seeded PRNG, sim decoupled
  from render. Required for replays, rollback netcode, and reproducible tests.
- **60 fps at 1080p** is a release gate, not a nice-to-have.

## 2. Quality bar

Work is not done when it runs. It is done when a **harsh critic subagent**,
shown our frame and a KOF XIII frame **blind and unlabelled**, picks ours. Every
visual system carries a critic score in `docs/PROGRESS.md`. Anything below the
bar goes back into the loop.

## 3. Architecture

Simulation is Ikemen-GO / M.U.G.E.N-shaped (state machine + CLSN boxes + command
parser), rendering is a bespoke NPR pipeline.

```
src/core/     fixed-timestep loop, seeded RNG, input buffer + motion parser
src/engine/   fighter entity, state machine, hit/hurtboxes, physics, combat,
              gauges (power/drive/HD), match + round flow
src/render/   renderer, fighting-game camera, NPR (cel + ink outline), post
              stack, VFX
src/art/      procedural texture synthesis, character meshes/rigs, stages
src/anim/     skeleton, clips, poser (sprite-snap quantization), IK
src/audio/    procedural SFX + music synthesis
src/ui/       HUD, screens
src/data/     roster frame data, move lists, stage defs
tools/        screenshot harness, blind-comparison critic harness
```

### Non-negotiable engine invariants

- Sim never reads `Date.now()` / `Math.random()` — only the tick counter and the
  seeded RNG. Render may read wall clock for interpolation only.
- Hit resolution order is fixed and documented; both fighters resolve from the
  same snapshot so trades are symmetric.
- Frame data lives in `src/data/`, never inline in logic.
